sync Model Fallback System — user manual
The Model Fallback System grew from a v2.0 cascade (rotate through fallback models when one fails) into a v2.5 resilience layer that also keeps the WebUI and event loop healthy. This page is the user manual — it explains each piece in plain English and tells you when (if ever) to disable it.

1. Overview

What you get out of the box:

  • Multi-cycle model rotation with cooldown and per-session permanent-failure tracking. If your primary model hits a 429, the cascade moves to the next fallback; if it hits a 401/402/404, the cascade marks it broken for the session and skips it on every later cycle.
  • WebUI resilience: a TTL cache + circuit breaker on the extensions lookup that throttles the 150 ms polling storm.
  • LLM error handling: a hard cap on hung utility calls, an opt-in history trim for ContextOverflow spirals, and a langchain v0 → v1 import shim for v1-only docker images.

v2.5 note: the standalone event-loop housekeeping loop (coroutine sweep + WebSocket keepalive pulse + stats tick) was removed — it was implemented the same day it shipped, never tested, and manifested as a per-minute housekeeping loop not alive respawn log line with no user-visible benefit. The housekeeping_enabled and second_pulse_path_enabled settings are still accepted for back-compat but are no-ops.

Every resilience feature can be toggled OFF independently. The defaults are conservative; turn things ON only if you see the symptoms the feature is designed to fix.

2. The model cascade (v2.0–v2.4)

When a model call fails, the cascade tries the next fallback instead of giving up. The system classifies errors into:

  • Rate Limits (429) — the model is placed on cooldown using the server's Retry-After header. The cascade skips it until the cooldown expires.
  • Auth Failures (401/403) — permanent skip for the entire session.
  • Credit Depletion (402) — permanent skip for the entire session.
  • Model Not Found (404) — permanent skip for the entire session.
  • Context Overflow — detected from the error message, permanent skip for the session.
  • Invalid JSON — triggers rotation to the next model (the agent retries with a different parser path).
  • Timeouts — retried with the next model after a brief delay (the Utility-model timeout guard sets the hard cap).

Settings in this section

  • Chat Model Timeout (default 300s) — per-request timeout for chat calls. The cascade counts each request, not the whole cascade.
  • Utility Model Timeout (default 300s) — per-request timeout for utility calls. Note that the Utility-model timeout guard (below) sets a second, outer cap; both apply.
  • Inter-Model Delay (default 2s) — pause between fallback attempts.
  • Max Cycles (1–10, default 4) — how many full passes through the fallback list before the agent gives up.
  • Cycle Delay (default 5s) — pause between cycles.

Recommended presets

Fast
2 cycles, 3s delay, 120s timeout
Good for testing with few fallbacks
Balanced

3. Resilience features (v2.2–v2.4)

Six independent pieces. Each one targets a specific failure mode in the WebUI / event-loop / LLM stack. The pieces share no state with each other and can be toggled ON / OFF independently.

3.1 Utility-model timeout guard v2.2

Symptom it fixes: a hung utility call (typically a slow ollama model on CPU) blocks the agent loop indefinitely. The cascade's per-request timeout fires after 300s, but the agent has already given up; you see a frozen WebUI.

What it does: wraps Agent.call_utility_model in asyncio.wait_for(...) with a hard cap (max_wait_s, default 120s). On timeout, the inner litellm coroutine is best-effort closed (via the memory_hardening plugin) and a RepairableException("utility_model_timeout") is raised so the LLM is told the utility failed.

Default: ON.

3.2 Event-loop housekeeping v2.2 REMOVED in v2.5

Removed in v2.5. The standalone while True housekeeping loop (coroutine sweep, WebSocket keepalive pulse, stats tick) and its job_loop safety net were deleted. The loop was a same-day fix that shipped before being tested, and the only symptom it ever produced in practice was a per-minute housekeeping loop not alive, respawning log line with no user-visible benefit. The housekeeping_enabled and second_pulse_path_enabled settings are still accepted in default_config.yaml for back-compat with hand-edited configs, but the toggle resolver treats them as no-ops and the runtime ignores them.

If a future agent-zero update ships an equivalent housekeeping loop, you can leave both keys at their default (false) and let the upstream one do the work. No migration step is required.

3.3 WebUI extensions cache v2.2

Symptom it fixes: the WebUI calls /api/load_webui_extensions whenever Alpine re-renders an extension point. During page lifecycle (init, settings open, plugin toggle, project switch) this can fire 10+ times per second, and each call walks every plugin's extensions/webui/ folder via files.find_existing_paths_by_pattern. With a slow filesystem mount you get a positive-feedback storm — the user sees it as "the WebUI is hanging."

What it does:

  • TTL cache (default 2s) — at most one filesystem walk per 2s, identical responses served from RAM. Auto-busts on the extension watchdog (plugin enable/disable, file edit) so user-visible state stays fresh.
  • Circuit breaker (default: open after 5 errors in 10s, recover after 30s) — when the filesystem is slow enough that get_webui_extensions itself raises, the breaker opens and the wrapper returns [] immediately for recovery_s seconds. Keeps the WebUI responsive even when the framework's FS layer is wedged.

Default: ON.

3.4 Context-size guard v2.3

Symptom it fixes: when the agent's conversation grows past the utility model's context window, every utility candidate returns ContextOverflow. The cascade can't recover from this in a single cycle because the chat history is already too long.

What it does: at message_loop_prompts_after it counts the total characters in loop_data.history_output. If the total exceeds max_chars (default 50000), the oldest messages are dropped until the budget is met, with a one-liner notice injected so the LLM knows the early turns were trimmed.

Default: OFF. Trimming can confuse the LLM (it loses the early conversation), so this is opt-in. Enable when you see cascading ContextOverflow errors across all utility candidates in a single cycle.

3.5 LangChain v0 → v1 import shim v2.4

Symptom it fixes: ModuleNotFoundError: No module named 'langchain.prompts' on langchain-v1-only docker images. The codebase still uses the v0 import path in helpers/call_llm.py; the v1 release moved that module to langchain_core.prompts.

What it does: at agent_init time, registers langchain_core.prompts under the legacy langchain.prompts path (and langchain_core.messages under langchain.schema) via sys.modules. The shim is a no-op on langchain v0.x installs (the legacy module is already in sys.modules and we leave it alone). A sentinel attribute marks the shim so uninstall is clean.

Default: ON.

4. Per-feature toggles

Each feature has a top-level boolean on context.settings:

Setting keyDefaultEffect when OFF
utility_timeout_guard_enabled true Utility call falls back to the cascade's per-request timeout (300s). Hung calls can freeze the loop longer.
housekeeping_enabled REMOVED false Setting is accepted for back-compat but is a no-op. The standalone housekeeping loop was deleted in v2.5; the job_loop safety net respawn logic was also removed.
second_pulse_path_enabled REMOVED false Setting is accepted for back-compat but is a no-op. The second socketio.emit pulse path was removed together with the housekeeping loop in v2.5.
webui_extensions_cache_enabled true get_webui_extensions is called directly. Polling storm returns on slow mounts.
context_size_guard_enabled false History is not trimmed. ContextOverflow spirals must be fixed by other means (a smaller model, shorter conversation).
langchain_compat_enabled true Shim is not installed. v0-style imports fail with ModuleNotFoundError on v1-only images.

Toggling the cache / shim / utility-timeout features takes effect on the next server start (the install hooks run at boot). Toggling the context-size-guard takes effect on the next agent turn (the hook re-resolves the config per call). The housekeeping and second-pulse-path toggles are no-ops in v2.5 (the underlying loop is gone) but the keys are still accepted on save.

The settings round-trip through helpers.plugins.get_plugin_config, which respects the framework's per-project / per-agent / global resolution chain. The config.json you see in the project directory is the persisted form.

5. When to disable a feature

Disable the utility-model timeout guard if:

  • You see RepairableException("utility_model_timeout") in the agent log on a model that is actually producing slow but correct output (raise max_wait_s instead).
  • You use a non-ollama utility model with a known slow first-byte time (raise the cap, or disable).

Disable the WebUI extensions cache if:

  • You develop a plugin and need zero-delay feedback when you save a file. The 2s TTL will hide edits for up to 2 seconds. The auto-bust on file-watch should catch most cases; if it doesn't, disable the cache during plugin development and re-enable when done.

Disable the context-size guard if:

  • You see the LLM forgetting early instructions after a trim. The notice injection helps but is not a substitute for an actually-fitting context. The right fix is usually a larger model window or a shorter conversation.

Disable the langchain shim if:

  • You are on langchain v0.x and the shim causes surprising behavior (it shouldn't — the shim is a no-op when the v0 module is already in sys.modules). Disable to remove the indirection.

6. Migration (upstream adds the equivalent)

If a future agent-zero release ships its own equivalent of one of these features, the recommended migration is:

  1. Toggle OFF the matching feature in this plugin.
  2. Restart the server.
  3. Confirm the upstream equivalent is active (e.g. the new keepalive ping in the server logs).
  4. If the migration is permanent, the corresponding helper file can be deleted:
    • helpers/utility_timeout.py
    • helpers/webui_extensions_cache.py
    • helpers/langchain_compat.py
    • the context-size-guard extension (extensions/python/message_loop_prompts_after/_10_context_size_guard.py)

Migration notes are also in AGENTS.md under each feature's section.

7. Observability — the stats endpoint

Read-only counters are exposed at GET /api/plugins/_model_fallback/stats: 

{
  "version": "2.5.0",
  "utility_timeout": {
    "calls_total": 89,
    "timeouts_total": 3,
    "max_observed_wait_s": 67.2
  },
  "extensions_cache": {
    "hits": 1842,
    "misses": 312,
    "circuit_open": false,
    "hit_rate": 0.855
  },
  "context_size_guard": {
    "trims": 0,
    "messages_dropped": 0
  },
  "langchain_compat": {
    "installed": true,
    "shims": {
      "langchain.prompts": true,
      "langchain.schema": false
    }
  }
}

The endpoint inherits the framework's requires_auth=True — the WebUI's logged-in session passes that transparently. The endpoint is read-only; no POST/PUT.
