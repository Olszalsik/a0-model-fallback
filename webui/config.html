sync Model Fallback System
Configure the multi-cycle fallback system for robust model switching when rate limits or errors occur.
⏱ Timeouts
How long to wait for a model response before switching to the next fallback. Increase for slow models (low TPS) or large responses.
Chat Model Timeout (seconds)
Timeout for chat model requests. Default: 300s (5 min).
Utility Model Timeout (seconds)
Timeout for utility model requests (memory, prompts). Default: 300s (5 min).
Inter-Model Delay (seconds)
Brief pause between fallback attempts to avoid hammering. Default: 2s.
🔄 Fallback Cycles
Number of complete cycles through all fallback models before giving up. Each cycle attempts all configured fallbacks once.
Max Cycles (1-10)
How many full cycles through the fallback list.
Cycle Delay (seconds)
Wait time between full cycles when all models failed.
🛡 Resilience features
Each piece is independent. Turn OFF what you don't need — a future agent-zero update may ship an equivalent and you can disable our version to avoid the double-fix. Per-feature detail is in the user manual (book icon above).
Utility-model timeout guard v2.2
Caps a hung utility call (typically ollama on CPU) at max_wait_s (default 120s) so the agent loop never freezes indefinitely. On timeout, the LLM is told the utility failed and can rephrase or skip.
WebUI extensions cache v2.2
2s TTL cache + circuit breaker on get_webui_extensions. Breaks the 150ms polling storm during page lifecycle and short-circuits to [] when the framework's filesystem layer raises repeatedly (slow mount). Auto-busts on plugin enable/disable.
Context-size guard (opt-in) v2.3
Trims the oldest messages in loop_data.history_output when total chars exceed max_chars (default 50000). Enable only if you see the cascade hit ContextOverflow on every utility candidate in a single cycle. Trimming can confuse the LLM if the early conversation mattered.
LangChain v0 → v1 import shim v2.4
Maps langchain.prompts / langchain.schema to langchain_core via sys.modules at agent_init. Fixes ModuleNotFoundError: langchain.prompts on langchain-v1-only docker images. No-op on langchain v0.x installs.

The advanced knobs below edit the nested <piece>.<key> sections of default_config.yaml. Use only if you understand the trade-off; the defaults are conservative.

Most of these are read at server boot. Changing them here requires a restart.

  • utility_timeout_guard.max_wait_s (default 120) — hard cap on a single utility call.
  • utility_timeout_guard.jitter_s (default 1.0) — random spread so concurrent agents don't lockstep.
  • webui_extensions_cache.ttl_s (default 2.0) — cache freshness window.
  • webui_extensions_cache.circuit_breaker_threshold (default 5) — errors in window before breaker opens.
  • context_size_guard.max_chars (default 50000) — trim threshold when enabled.
  • context_size_guard.min_messages (default 2) — never trim below this count.

v2.5: the standalone event-loop housekeeping loop and the second WebSocket pulse path were removed. The housekeeping: and second_pulse_path_enabled config keys are still accepted for back-compat but are no-ops.
